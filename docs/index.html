1. SDK in detailSDK 1.0.13 · runtime 1.0.83

Review one repository, without changing its source

Our task: inspect examples/01_simple_chat.py for error handling and cleanup, then add GitHub issue context.

With a direct model API

  • Your code sends a request and receives text or proposed tool calls.
  • Your code must dispatch tools, return their results, and repeat model calls.
  • You implement conversation state and the surrounding controls.

With the Copilot SDK

  • The Copilot runtime manages the model/tool loop and session state.
  • The SDK exposes typed events, tool registration, and host callbacks.
  • Your application still supplies credentials and authorizes access.

The first sample only receives a supplied repository description. It cannot inspect files until a tool is exposed.

1. SDK in detailSource03 / 18
1. SDK in detailSDK 1.0.13 · runtime 1.0.83

One user request can trigger several model calls

Example: ask the assistant to inspect a Python file through a custom host tool.

StepOwnerOperation
1Application → SDKsend_and_wait(prompt, timeout=60) sends the user request.
2Runtime → modelSend conversation context and the available tool schemas.
3Model → runtimePropose inspect_python_file with the file argument.
4Runtime → hostRequest permission; the host returns an approval or rejection.
5Host toolOn approval: validate the argument, read the allowed file, return AST metadata.
6Runtime → modelAppend the tool result to the conversation and call the model again.
7Runtime → SDKEmit the final assistant message and idle event; the wait completes.

A rejection skips execution. Built-in tools run in the runtime; custom Python handlers run in the host. SDK assistant.turn events describe individual model iterations.

1. SDK in detailSource04 / 18
1. SDK in detailSDK 1.0.13 · runtime 1.0.83

Tool access has three separate controls

Expose a capability

ToolSet and available_tools select which tool schemas the model can use. Hiding a tool is not OS isolation.

Authorize a request

on_permission_request evaluates a proposed operation. Human input is not automatically authorization.

Limit execution

SandboxConfig restricts runtime-launched tools where a backend is available. Custom host handlers need separate containment.

The workshop uses read-only tools and disposable data. A sandbox bypass intentionally removes the sandbox for one approved operation.

4. SamplesSource08 / 18
4. SamplesSDK 1.0.13 · runtime 1.0.83

Stream the review plan and require a final message

  • available_tools=[] makes this turn text-only.
  • Subscribe before sending; assistant.message_delta contains chunks, not guaranteed tokens.
  • A timeout or session error raises. An idle session without a final message returns None.
  • Always remove the event listener in finally.
examples/01_simple_chat.py · inside a streaming session
unsubscribe = session.on(on_event)
try:
    reply = await session.send_and_wait(REVIEW_PROMPT, timeout=60)
    if reply is None:
        raise RuntimeError("Session became idle without an assistant message.")
    if not saw_delta:
        print(reply.data.content, end="", flush=True)
finally:
    unsubscribe()

Run: python examples/01_simple_chat.py. This output is a plan based on supplied context, not a claim that files were inspected.

4. SamplesSource09 / 18
4. SamplesSDK 1.0.13 · runtime 1.0.83

Add a typed repository-inspection tool

  • A Pydantic parameter type defines the tool's input schema.
  • The handler validates an explicit file allowlist and returns AST metadata.
  • ToolSet exposes this custom tool without granting built-in filesystem tools.
  • A recorded handler invocation proves the read; the model's summary does not.
examples/02_custom_tools.py · tool declaration
class FileParams(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    file: Literal[
        "examples/01_simple_chat.py", "examples/02_custom_tools.py"
    ] = Field(description="An explicitly allowlisted workshop Python file.")

@define_tool(description="Inspect an allowlisted Python sample's AST metadata")
async def inspect_python_file(params: FileParams) -> dict:
    metadata = read_python_metadata(params)
    INSPECTIONS.append(metadata)
    encoded = json.dumps(metadata, sort_keys=True)
    print("[host tool] inspect_python_file result=" + encoded)
    return metadata

Run: python examples/02_custom_tools.py. The complete source contains the handler and its permission policy.

Select the reviewer and check the selected agent

  • Researcher and reviewer are configurations in one session, not parallel agents.
  • Both are restricted to read tools for the same repository.
  • Conversation context remains available when selecting the reviewer.
  • Check agent.name before sending the next prompt. The selection RPC is experimental.
examples/03_custom_agents.py · selection and verification
await session.rpc.agent.select(AgentSelectRequest(name="reviewer"))

# Confirm the swap before we send anything else.
current = await session.rpc.agent.get_current()
if current.agent is None or current.agent.name != "reviewer":
    raise RuntimeError("The reviewer persona was not selected.")

4. SamplesSDK 1.0.13 · runtime 1.0.83

Observe repository reads with hooks

  • on_pre_tool_use runs before a tool call.
  • on_post_tool_use handles successful execution.
  • on_post_tool_use_failure handles failed execution.
  • These handlers log tool names. They do not enforce a policy or create a sandbox.
examples/04_hooks.py · pre-call and success hooks
async def on_pre_tool_use(input_data, invocation):
    print(f"[pre]  {input_data['toolName']}")
    return None

async def on_post_tool_use(input_data, invocation):
    print(f"[post] {input_data['toolName']} succeeded")
    return None

Run: python examples/04_hooks.py. Inspect the host trace alongside the repository answer.

4. SamplesSDK 1.0.13 · runtime 1.0.83

Add current GitHub issues through MCP

  • The remote GitHub MCP connection uses its own bearer credential.
  • Resolve the token at runtime; never print it or place it in source.
  • Use the read-only server header and an issue-tool allowlist.
  • Correlate a matching MCP start and successful completion. Zero open issues is a valid result.
examples/05_mcp_servers.py · remote server configuration
def build_mcp_servers(token: str) -> dict:
    return {
        "github": {
            "type": "http",
            "url": "https://api.githubcopilot.com/mcp/",
            "headers": {
                "Authorization": "Bearer " + token,
                "X-MCP-Readonly": "true",
            },
            "tools": GITHUB_TOOLS,
        },
    }

Run: python examples/05_mcp_servers.py. Copilot model login is not a replacement for MCP credentials.

4. SamplesSDK 1.0.13 · runtime 1.0.83

Resume the review in a second process

  • The first process stores the review file and focus in conversation context.
  • The second process uses the same session ID and runtime state storage.
  • The resume prompt must not repeat the facts being recalled.
  • Re-register host callbacks and tools. Session exit detaches; it does not delete saved state.
Two separate Python processes
SID="repository-review-$(date +%s)"
python examples/06_session_resume.py \
  --session-id "$SID"

python examples/06_session_resume.py \
  --resume --session-id "$SID"

A session ID identifies state; it is not authorization to access another user's conversation.

Appendix · Runtime deploymentSDK 1.0.13 · runtime 1.0.83

Managed child or existing runtime

SDK-owned process

  • Default: provision and start the release-matched runtime over stdio.
  • Use RuntimeConnection.for_stdio(path=...) for an explicit executable.
  • Client exit stops the child it owns.

Existing process

  • Use RuntimeConnection.for_uri(...) to connect to a running runtime.
  • The host protects the endpoint and owns process lifecycle.
  • State storage and request routing must survive reconnects.

These are process-ownership choices. Neither choice provides application user authentication or tenant isolation.

Appendix · AuthenticationSDK 1.0.13 · runtime 1.0.83

Credential source is not session authorization

Credential pathUse and limitations
Copilot CLI loginLocal signed-in user's eligible Copilot identity.
Explicit per-session tokenThe host supplies an eligible user's or application's credential.
Environment tokenCOPILOT_GITHUB_TOKEN, GH_TOKEN, or GITHUB_TOKEN; eligibility and policy still apply.
github_token_providerAcquire and refresh short-lived Copilot credentials; do not combine with a static session token.
Generic MCP connectionSeparate headers or an implemented OAuth callback; not inherited automatically from model login.

A token's presence does not prove Copilot entitlement. Credential ownership does not replace authorization for a particular saved session.

Appendix · BYOKSDK 1.0.13 · runtime 1.0.83

Configure inference with your own provider

  • ProviderConfig supplies endpoint, wire protocol, and authentication.
  • The model is a create_session argument, not a ProviderConfig field.
  • api_key, bearer_token, or bearer_token_provider depend on provider support.
  • Provider billing does not determine MCP credentials, tool egress, or all runtime traffic.
Configuration example · requires an eligible endpoint
provider = ProviderConfig(
    type="openai",
    base_url=os.environ["MODEL_BASE_URL"],
    api_key=os.environ["MODEL_API_KEY"],
    wire_api="responses",
)
session = await client.create_session(
    provider=provider,
    model=os.environ["MODEL_ID"],
    available_tools=[],
)

This is optional configuration, not the default of the eight samples. Select a compatible API and tool-capable model for your endpoint.
