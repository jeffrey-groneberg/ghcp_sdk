01 SDK im Detail

The agent loop, packaged. The control plane is yours.

Copilot CLI is great in a terminal. The SDK is what you reach for when you want to embed the same agent loop — tools, permissions, MCP, hooks, and persistence into your own app.

  • Same runtime engine and JSON-RPC protocol used by Copilot CLI
  • Runtime/account policy decides available models; inspect list_models()
  • Built-in tools vary by runtime, platform, and session configuration
  • Resume persisted sessions by ID when the same state storage is available
  • Your app still owns identity, authorization, workspace isolation, routing, and UI

01 SDK im Detail

The whole first app fits on one slide.

  • CopilotClient owns the managed runtime lifecycle.
  • create_session opens a persisted conversation.
  • available_tools=[] makes this first turn text-only.
  • send_and_wait raises on timeout/session error; None means idle without a final message.
01_simple_chat.py 
from copilot import CopilotClient

async with CopilotClient() as client:
    async with await client.create_session(
        available_tools=[],
    ) as session:
        reply = await session.send_and_wait(
            "Explain the SDK in 3 sentences.", timeout=60,
        )
        if reply is None:
            raise RuntimeError("No final message")
        print(reply.data.content)

01 SDK im Detail

Events stream progress. Completion stays bounded.

session.send() dispatches a turn and returns its message ID. Typed events carry deltas, tool activity, errors, and idle state.

send_and_wait composes the common completion path: events still reach listeners while timeout and session errors propagate to the host.

streaming=True match / case bounded wait
event_model.py 
async with await client.create_session(
    on_permission_request=PermissionHandler.approve_all,
    available_tools=[],
    streaming=True,
) as session:
    def on_event(event):
        match event.data:
            case AssistantMessageDeltaData(delta_content=d):
                print(d or "", end="", flush=True)
    session.on(on_event)
    await session.send_and_wait(
        "Explain the SDK in 3 sentences.", timeout=60,
    )
    print()

Tool and session surfaces share one runtime.

The runtime merges first-party tools, host-defined Python tools, and MCP tools. Exact availability depends on runtime, platform, account, and session configuration.

BUILTIN

Runtime tools

Examples include view, glob, grep, edit, and platform shell tools.

CUSTOM

Your Python functions

Register with @define_tool; handlers run in the host Python process unless you isolate them separately.

MCP

External servers

Local stdio or remote HTTP/SSE servers join the same catalogue with independent configuration and authentication.

ask_user is a built-in human-input tool. session_id is persisted lifecycle state, not a tool or authorization boundary.

01 SDK im Detail

Exposure is not approval. Approval is not containment.

Security depends on layers. Each answers a different question; none substitutes for the others.

EXPOSE

What can the model see?

ToolSet, available_tools, and excluded_tools shape the catalogue.

DECIDE

May this call run?

Permission callbacks approve or reject. Pre-tool hooks can also ask, deny, allow, or modify arguments. Managed settings express allow, ask, and deny policy.

CONTAIN

What can execution reach?

Experimental SandboxConfig constrains runtime tools. Your app still owns process, tenant, secret, and network isolation.

02 Abgrenzung zur CLI

CLI and SDK share an engine, not a user experience.

Choose the CLI when a person works interactively in a terminal. Choose the SDK when your application must own the surface and lifecycle.

CLI

Interactive product

Built-in terminal UI, user-driven conversation, local defaults, slash commands, and direct human supervision.

SDK

Application component

Your UI, callbacks, sessions, credentials, runtime ownership, observability, and integration into a larger product.

The SDK does not replace the CLI runtime. It exposes that engine programmatically through language-native APIs and JSON-RPC.

02 Abgrenzung zur CLI

Two ownership models. Deployment choices underneath.

SDK-OWNED

Managed child runtime

Default stdio path. The SDK provisions, starts, and stops its runtime. Pre-download or vendoring changes packaging, not ownership.

HOST-OWNED

Existing runtime service

Connect with RuntimeConnection.for_uri(...). The host protects the endpoint, storage, process lifecycle, routing, and multi-user boundaries.

Shared or multi-user hosts use mode="empty" with explicit storage. TCP, containers, and horizontal scale are deployment variants.

Application ownership has production consequences.

Production services must add the boundaries that a local sample deliberately omits.

ID

Identity

Bind every client and session to an authenticated principal.

OWN

Session ownership

Authorize create, resume, steering, and deletion for that principal.

FS

Workspace isolation

Separate repositories, state directories, temp files, and custom tools.

FLOW

Routing and concurrency

Serialize turns, route persisted sessions, and enforce resource limits.

OBS

Observability

Trace requests and tool outcomes without logging secrets or private content.

NET

Secrets and network

Use least-privilege credentials, egress policy, and explicit MCP authentication.

Where the SDK earns its place.

Reach for the SDK when the agent must live inside another product or automated workflow.

  1. Developer tools — IDE, portal, dashboard, or internal CLI.
  2. Automation — review, triage, documentation, and CI analysis.
  3. Multi-user products — app-owned identity, UI, sessions, and policy.

03 Möglichkeiten

Four identity boundaries. Pick one deliberately.

USER

Interactive user

CLI login uses the signed-in identity's Copilot entitlement. Best for local and desktop workflows.

OAUTH

Per-user application token

OAuth App or GitHub App user tokens are passed explicitly. Authorize session ownership before resume.

ENV

Environment-carried token

COPILOT_GITHUB_TOKEN, GH_TOKEN, then GITHUB_TOKEN may carry a user or installation identity. Apply the corresponding owner and organization policy.

BYOK

Provider identity

Use provider API keys or bearer-token callbacks. Inference uses that provider's billing and access boundary.

github_token_provider rotates short-lived session credentials. Generic MCP servers still own separate headers or OAuth.

03 Möglichkeiten

Your provider. Your model. Your billing boundary.

Choose an OpenAI-compatible or Anthropic endpoint with provider. Inference is billed by that provider, not Copilot. Tool traffic, telemetry and data residency need their own configuration.

Supported providers

  • Microsoft Foundry — type: "openai" for /openai/v1/; keys or Entra tokens
  • Native Azure endpoint — type: "azure" with Azure-specific options
  • OpenAI direct — type: "openai" + api_key
  • Anthropic — type: "anthropic" for Claude Sonnet/Opus
  • Ollama / Foundry Local — local inference; this alone does not make the app offline
  • bearer_token_provider — refresh Entra tokens via Azure Identity / managed identity
azure_foundry_byok.py 
import os
from copilot import CopilotClient
from copilot.session import ProviderConfig

provider = ProviderConfig(
    type="openai",
    base_url="https://my-foundry.openai.azure.com/openai/v1/",
    api_key=os.environ["FOUNDRY_API_KEY"],
    wire_api="responses",           # GPT-5 family
)

async with CopilotClient() as client:
    async with await client.create_session(
        provider=provider, available_tools=[],
        model=os.environ["FOUNDRY_MODEL"],
    ) as session:
        await session.send_and_wait("Hi", timeout=120)

EX 02 Custom tools

Hand the agent a Python function.

@define_tool packages a sync or async function plus a Pydantic schema into a tool the model can call.

Field(description=…) explains each parameter. In 1.0.13, cancelled requests cancel async tool tasks too: clean up in finally, and let cancellation propagate.

@define_tool pydantic send_and_wait
02_custom_tools.py 
class WeatherParams(BaseModel):
    city: str = Field(description="City, e.g. 'Seattle'")

@define_tool(description="Generate fictional demo weather")
async def get_weather(params: WeatherParams) -> dict:
    return {"city": params.city,
            "temperature_c": random.randint(-5, 35),
            "condition": "sunny",
            "source": "fictional demo"}

async with await client.create_session(
    on_permission_request=PermissionHandler.approve_all,
    tools=[get_weather],
    available_tools=ToolSet().add_custom("get_weather"),
) as session:
    reply = await session.send_and_wait(
        "Fictional weather in Tokyo and Berlin.", timeout=60)

EX 03 Custom agents

Multiple personas. One session. Hot swap.

A custom agent is a named prompt that can have its own tool restrictions and MCP servers. Explicitly set tools when scoping is required.

Switch mid-conversation with session.rpc.agent.select(…) — history is kept, persona is replaced. Verify with rpc.agent.get_current().

The generated selection RPC is experimental; keep the handoff explicit and verify the active agent instead of inferring from tone.

custom_agents rpc.agent.select rpc.agent.get_current
03_custom_agents.py 
AGENTS = [
    {"name": "researcher", "display_name": "Research Agent",
     "tools": ["grep", "glob", "view"],
     "prompt": "Explore code. Never modify."},
    {"name": "reviewer", "display_name": "Review Agent",
     "tools": ["grep", "glob", "view"],
     "prompt": "Review for bugs and clarity."},
]

async with await client.create_session(
    custom_agents=AGENTS, agent="researcher",
    available_tools=ToolSet().add_builtin(["grep", "glob", "view"]),
    on_permission_request=PermissionHandler.approve_all,
) as s:
    await s.send_and_wait("What language is this?", timeout=120)
    await s.rpc.agent.select(AgentSelectRequest(name="reviewer"))
    cur = await s.rpc.agent.get_current()  # proves swap
    await s.send_and_wait("Review 01_simple_chat.py", timeout=120)

EX 04 Hooks

Cross-cutting concerns, without polluting tools.

The stable Python SessionHooks type exposes ten callbacks. This sample focuses on pre-tool, success, and failure.

on_post_tool_use handles success. Register on_post_tool_use_failure separately for failures. None keeps default behavior. Hooks support audit and defense-in-depth; they are not an OS or tenant boundary.

on_pre_tool_use on_post_tool_use permissionDecision
04_hooks.py 
async def on_pre_tool_use(input_data, invocation):
    print(f"[pre]  {input_data['toolName']}")

async def on_post_tool_use(input_data, invocation):
    print(f"[post] {input_data['toolName']} done")

async def on_post_tool_use_failure(data, invocation):
    print(f"[failed] {data['toolName']}")

async with await client.create_session(
    on_permission_request=PermissionHandler.approve_all,
    available_tools=ToolSet().add_builtin(["glob", "view"]),
    hooks={
        "on_pre_tool_use": on_pre_tool_use,
        "on_post_tool_use": on_post_tool_use,
        "on_post_tool_use_failure": on_post_tool_use_failure,
    },
) as session:
    await session.send_and_wait("List files.", timeout=120)

EX 05 Remote GitHub MCP

Separate connection. Separate authentication.

A server configured through mcp_servers is an independent HTTP connection. Copilot CLI sign-in authenticates the model path, not arbitrary MCP headers.

This sample uses a bearer token header. The hosted server also supports OAuth when the host implements on_mcp_auth_request. A real MCP event is required before the turn counts as successful.

mcp_servers Bearer or OAuth ToolSet allowlist
05_mcp_servers.py 
mcp_servers = {
    "github": {
        "type": "http",
        "url": "https://api.githubcopilot.com/mcp/",
        "headers": {
            "Authorization": f"Bearer {token}",
            "X-MCP-Readonly": "true",
        },
        "tools": GITHUB_TOOLS,
    },
}
async with await client.create_session(
    mcp_servers=mcp_servers,
    available_tools=available_tools,
    on_permission_request=PermissionHandler.approve_all,

EX 06 Session persistence

New process. Same persisted conversation context.

Keep session.session_id, or choose your own ID. The CLI persists conversation state on disk; a new process must use the same state storage.

resume_session restores persisted context. Re-register handlers/tools and re-supply BYOK credentials, MCP authentication/configuration, and injected managed_settings. Context exit detaches; delete_session removes state.

session_id resume_session --resume
06_session_resume.py 
SESSION_ID = "demo-session-resume"

# Turn 1 — fresh process, store memory
async with await client.create_session(
    session_id=SESSION_ID, available_tools=[],
    on_permission_request=PermissionHandler.approve_all,
) as session:
    await session.send_and_wait(
        "My name is Jeffrey. Remember it.", timeout=60)

# Turn 2 — new process, recall memory
async with await client.resume_session(
    SESSION_ID, available_tools=[],
    on_permission_request=PermissionHandler.approve_all,
) as session:
    await session.send_and_wait(
        "What is my name?", timeout=60)

EX 07 Human in the loop

Match the action first. Ask the human second.

The sample first requests structured elicitation, validates the name schema, and falls back to a narrowly validated legacy callback only when the runtime lacks that structured schema.

Permission requests are typed. On POSIX this sample accepts one fixed printf argument vector; Windows uses one fixed PowerShell command. It rejects sandbox bypass and surfaces managed_approval_required.

Only after machine validation does the terminal ask the human. Approval is once; timeout returns user-not-available.

on_permission_request PermissionDecisionApproveOnce
07_human_in_the_loop.py 
# Stage 1: validate structured ask_user schema
# Fallback: one freeform name only
from copilot.rpc import PermissionDecisionApproveOnce, PermissionDecisionReject
from copilot.session_events import PermissionRequestShell

async def on_permission_request(request, invocation):
    match request:
        case PermissionRequestShell(full_command_text=cmd):
            if not is_expected_command(cmd):
                return PermissionDecisionReject()
            answer = await read_answer(
                "Approve once? [y/N]: ", timeout=120)
            if answer.lower() == "y":
                return PermissionDecisionApproveOnce()
    return PermissionDecisionReject()

EX 08 Sandbox

Enable containment. Bypass only by exception.

SandboxConfig constrains runtime-launched tools. The API is experimental and backend/platform dependent.

DEFAULT

Constrain execution

Grant the working directory, deny the demo vault, and disable outbound plus loopback network access.

enabled=True

BYPASS

Ask separately

allow_bypass=True only permits a distinct permission request. Approve one exact operation or keep it blocked.

approve once

Host-side Python tool handlers are not contained automatically. Sandboxing is defense-in-depth, not a VM, container, authorization system, or tenant boundary.
